# Fix My City

## Put the demo online with Render

This project includes a Render Blueprint at the repository root (`render.yaml`) that deploys the website and creates a shared PostgreSQL database. To deploy it, push the whole project folder to a GitHub repository, then in Render choose **New + → Blueprint**, connect that repository, and apply the `fix-my-city` service. Render will provide a public `onrender.com` URL. On first setup, enter `STAFF_EMAIL` and a strong `STAFF_PASSWORD` for the employee portal. Set `GROQ_API_KEY` in the Render service Environment settings to enable the resident AI guide and AI classification. Add `GOOGLE_MAPS_API_KEY` if you want Google address lookup; it can stay blank otherwise. The session secret is generated by the Blueprint. The default Groq model is `openai/gpt-oss-20b`; change `GROQ_MODEL` if you want another model available to your GroqCloud project.

The app uses PostgreSQL for reports. New reports submitted from any device are stored in the shared database and available in the employee portal; employee status changes sync back to public report tracking. Staff reports refresh automatically every 20 seconds while the staff dashboard is open. To deploy on another Node host, set its root directory to `outputs`, build command to `npm install`, start command to `npm start`, and configure `DATABASE_URL`, `STAFF_EMAIL`, `STAFF_PASSWORD`, and a long random `APP_SESSION_SECRET`. It listens on the host-provided `PORT` and has a `/healthz` health check.

The public website is served from `index.html` at the site root (`/`) for reporting and tracking. It includes an AI guide that can prepare a report draft from a resident’s description and location; residents review the draft and submit it themselves. The guide requires `GROQ_API_KEY` in Render. The employee website is served from its own `staff.html` page at `/staff`; it opens directly to staff sign-in and hides resident pages. Both websites keep the same visual style and use the same server API and PostgreSQL database. For example, if the Render URL is `https://your-app.onrender.com`, share that URL with residents and `https://your-app.onrender.com/staff` with employees.

The first deployment seeds the employee account from `STAFF_EMAIL` and `STAFF_PASSWORD`. After signing in, use **Employee details** to change the email and/or password; the updated credentials are stored as a password hash in PostgreSQL and remain in effect after redeploys. The login form includes a password visibility toggle, and the employee workspace has a log-out button.

**Hackathon demo limits:** Render's free PostgreSQL databases currently expire 30 days after creation and have no backups. Upgrade the database or use another persistent PostgreSQL service if you need to keep reports beyond the demo. This is a prototype, not a production civic records system; before handling real sensitive reports, add stronger account management, role-based staff accounts, abuse protection, backups, and a privacy/data-retention policy. [Render free plan limitations](https://render.com/docs/free)

## Run the website

Install Node.js 18 or newer and PostgreSQL. Set `DATABASE_URL` to your PostgreSQL connection string, then set staff credentials and a long random session secret in the same PowerShell terminal:

```powershell
$env:DATABASE_URL="postgresql://user:password@localhost:5432/fix_my_city"
$env:STAFF_EMAIL="staff@example.org"
$env:STAFF_PASSWORD="choose-a-strong-password"
$env:APP_SESSION_SECRET="use-a-long-random-secret"
npm install
npm start
```

Then open <http://127.0.0.1:4173>. The app needs its Node server and PostgreSQL connection; opening the HTML file directly will not load or save shared reports.

## Turn on Groq issue analysis and the civic assistant

Set your API key in the same PowerShell window and start the server:

```powershell
$env:GROQ_API_KEY="your-groq-api-key"
node server.js
```

The server calls Groq’s OpenAI-compatible Chat Completions API at `https://api.groq.com/openai/v1/chat/completions`. It uses `openai/gpt-oss-20b` by default; if your GroqCloud account supports another model, set `GROQ_MODEL` before starting the server:

```powershell
$env:GROQ_MODEL="your-available-model"
node server.js
```

Create an API key in [GroqCloud](https://console.groq.com), then add it in Render as `GROQ_API_KEY`. Keep the key in Render’s server environment; never add it to HTML or commit it to GitHub. Groq’s free tier has usage limits; check the current [rate limits](https://console.groq.com/docs/rate-limits) and [supported models](https://console.groq.com/docs/models). The form’s **Analyze with AI** button sends only the issue description and selected category; it does not send name, contact, address, GPS or photos. The resident chat guide sends the conversation (which may include the location the resident provides) to Groq to draft a complaint. The guide does not submit reports; the resident reviews the fields and submits the form. Keep personal details out of chat messages. If AI is unavailable, residents can still use the manual report form and local keyword suggestions.

## Turn on Google Maps address lookup

In Google Cloud, enable the Geocoding API for a project with billing enabled, and create a restricted API key. Keep it on the server, restrict it to the Geocoding API, and set a quota. In the same PowerShell window, set both keys before starting the server:

```powershell
$env:GROQ_API_KEY="your-groq-api-key"
$env:GOOGLE_MAPS_API_KEY="your-google-maps-key"
node server.js
```

The app can then turn a GPS fix into a readable Google Maps address, or look up coordinates from a typed address. Without a Google Maps key, address text is still saved and a link opens the typed location or GPS point in Google Maps. Google Maps reverse geocoding uses coordinates to return a human-readable address; Maps URLs can open a search or pin without an API key. See [Google reverse geocoding](https://developers.google.com/maps/documentation/geocoding/guides-v3/requests-reverse-geocoding) and [Maps URLs](https://developers.google.com/maps/documentation/urls/get-started).

## Shared report privacy

Public report tracking requires the private report ID and exposes the issue category, location, status, and submitted date. Reporter name, contact details, and the all-reports staff list require the employee session. Keep database credentials and staff passwords in the hosting provider's secret settings; never put them in the HTML or GitHub repository.

## Replace reports with Tamil Nadu demo data

The optional `npm run seed:demo` command permanently replaces every row in `civic_reports` with 100 fictional Tamil Nadu sample reports: 20 unassigned, 20 assigned, and 60 resolved. Each sample is marked `DEMO SAMPLE` and has no reporter name, phone, or GPS coordinates. It prints the database target and requires the exact confirmation phrase before changing anything. Set `DATABASE_URL` to the intended database first. Do not run it against production reports you need to keep.

The server uses Groq’s OpenAI-compatible chat completions endpoint. See the [Groq quickstart](https://console.groq.com/docs/quickstart), [model list](https://console.groq.com/docs/models), and [rate limits](https://console.groq.com/docs/rate-limits).
